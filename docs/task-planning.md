# 会后任务计划

入口：实时看板 → **任务计划**。

1. 记录项目小组讨论，会议结束后点击「生成任务草稿」。排期起点默认是浏览器所在日期，可自行修改。
2. 点选任务，核对负责人、开始日期、截止日期和前置任务。「应用修改」只改本地草稿，「保存草稿」写入本机。
3. 点击「确认并开始执行」。确认要求任务都有负责人和日期；任务不能依赖自身、不能循环，后续任务必须在前置任务截止日期的次日或之后开始。
4. 在「执行计划」手动更新未开始、进行中、已完成。重新生成会建立独立草稿，不覆盖正式计划；确认替换时同一任务 ID 的进度会保留。
5. 「理解这份计划」仅查询当前会议原话与已保存的当前草稿/正式计划。回答关联的任务可点击查看，原话引用可展开核对。
6. 「导出计划」下载当前所选计划的 Markdown。原有会议纪要和本地 JSON 快照也会包含任务计划；共享的旧版看板链接仍仅展示会议图。

## 真实 AI 与规则演示

复用后端现有 OpenAI 兼容客户端。在 `backend/.env` 配置 `AMO_LLM_ENABLED=1`、`OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`，重启后端即可。不要提交 `.env` 或密钥。

真实 AI 可以从原话或现有行动项提取任务、提出日期/依赖建议并解释编排。模型提取的任务须关联当前会议的行动项，或提供能逐字核对的原话引用。没有明确期限时，依据参考日期、工期和前置任务给出建议日期。所有生成结果先进入草稿，由人核对确认。

未启用真实 AI 时页面明确显示「规则演示」。规则只读取已有行动项、补充日期建议，不猜测负责人和依赖；问答仅查询任务名、负责人、顺序等结构化信息。这适合验证软件流程，不能作为真实模型的效果证明。例：原话提出「小李写方案，小王在方案确认后做原型」，演示模式需人工补负责人和依赖，真实 AI 路径可提出这些建议。

本版本以单机运行、小组共同查看为范围，没有成员登录、在线协作或消息通知。多人使用同一服务时，以计划版本号阻止过期写入；冲突时会保留当前输入，需要刷新后重新对照修改。

## 数据与实现

- 计划单独保存在后端存储根目录的 `task_plans/<meeting_id>.json`，具有独立递增版本。草稿与正式计划在同一文件中原子保存，写入失败不发布成功。
- 原始会议图保持自己的版本。确认计划不修改会议图的节点字段；正式任务计划里的负责人、日期和进度是后续执行依据。
- 依赖图沿用 X6，以稳定任务 ID 引用前置任务；完整计划保存前校验 DAG。排期采用按日的「完成后次日开始」，不处理小时、周末、假期或成员资源冲突。
- 每份计划最多 100 个任务；真实模型输入超过 8 万字符会拒绝，避免静默漏掉会议内容。引用范围在服务端再次校验；来源存在不代表模型理解一定正确，仍需要人工核对。
- 文件锁适用于当前单进程后端。多进程/跨机器部署需要数据库事务与跨进程并发控制。

借鉴：[Frappe Gantt 的任务和依赖数据结构](https://github.com/frappe/gantt)、[xyflow 的依赖循环检查](https://reactflow.dev/examples/interaction/prevent-cycles)。没有引入新图表库。
