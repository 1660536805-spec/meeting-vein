# 会脉产品完整化与可用性优化实施方案

> 版本：2026-10-06 · 状态：实施中 · 适用基线：`ai_meeting_organizer-fusion` 本地工作树（实际分支和既有变更见基线报告）
> 本文描述目标、修改顺序和验收办法；表中的「应实现」不表示当前已经具备。执行前先核对工作树，因为当前已有未提交改动。

## 0. 目标与依据

**目标：**把当前能展示 200 句会议数据的 Demo，做成从创建会议、输入、结构化整理、人工纠错、追溯到交付均能闭环的可用产品。首个交付形态是**单机部署、单人编辑、多人只读查看**的内测版；腾讯会议接入、跨设备安全分享和多人同时编辑单列为后续里程碑，不用现有本机链接冒充已交付。

**产品原则：**AI 是会议秘书，只维护看板；主持权和最后决定权归人。不录存原始音频；原话与结构化结果可以保存。每条 AI 结论可追溯到发言，每项人工修改有优先权和撤销途径。Mock 与真实 ASR/LLM 的结果必须明确区分。

**资料优先级：**[需求大纲](../../../doc/Design.md)决定产品目标与边界；[产品审计和优化方向](../../../doc/Product_Optimization_Plan_2026-10-06.md)记录当前页面和仓库证据；[融合设计](../specs/2026-09-23-meeting-product-integration-design.md)、[实时转写设计](../specs/2026-09-25-live-asr-design.md)解释原方案；**当前代码**决定已有能力。旧设计与现代码不一致时，先在本方案中选定目标契约，再同步修改设计文档。

**技术栈：**Vite + TypeScript + AntV X6；FastAPI + LangGraph；本地 Store A/Store B；本地 ASR（Paraformer 流式、SenseVoice）；可配置 OpenAI 兼容 LLM。现有应用入口分别在 `frontend/src/main.ts`、`backend/app/server.py`、`local_asr/backend/app/main.py`。

## 2. 核心用户流程与页面约束

| 场景 | 页面行为 | 完成标准 |
| --- | --- | --- |
| 会前 | 首页建会，填写标题/议程；可手改识别出的顶层议题；显示输入来源和模式。 | 3 步内进入空看板；取消或解析失败时议程原文仍在。 |
| 会中 | 顶部显示会议状态、当前输入/处理状态；默认先显示“结论/未决/下一步”概览；可切议题树和局部关系图。 | 首屏无需缩到 75% 就能读关键内容；任一卡片两次点击内到原话。 |
| 纠错 | 点节点改文本、类型、归属、重要性、状态；锁定、撤销和版本比较。 | 保存反馈明确；AI 后续更新不覆盖受保护字段；失败时编辑内容不消失。 |
| 会后 | 主持人结束会议，检查未决、待办负责人和期限，生成 Markdown/HTML 纪要与只读快照。 | 导出包含来源、未解决项和不确定标记；复制链接能在预期范围访问。 |
| 异常 | ASR、LLM、网络、浏览器刷新、服务重启有可恢复入口。 | 不把“已接收”显示成“已整理”；不会静默丢失分段发言。 |

界面按**概览 → 议题树 → 局部图 → 证据/编辑抽屉**分层。桌面端保留图谱；窄屏默认概览/议题树，图谱为可进入的全屏视图。左侧原话栏不能覆盖图根节点；弹层与看板娘不能遮挡编辑和来源。键盘可聚焦所有交互项，状态不能只用颜色表达。

## 3. 必须先定的数据契约

### 3.1 节点归属与语义关系分离

当前 `frontend/src/issues-view.ts`、`frontend/src/board/render.ts` 将各类有向边都参与父子推导；`support/oppose/duplicate/replace` 不能作为稳定的树父级。目标定义：

```text
Node.data.parent_id: string | null    # 唯一结构归属；根议题为 null
Edge.data.relation: support | oppose | duplicate | replace | derive
Board.schema: amo.board/v2
```

`parent_id` 仅负责议题树、布局和面包屑；语义边仅负责论证、冲突与演进。添加/改父级必须验证目标存在、同会议、不得自挂或成环；删除父节点前要选择子节点重挂或一起删除。AI 建议和人工编辑都经同一验证函数。禁止因一条反对边把节点挪入对方议题。

旧 `amo.board/v1` 数据**读取时可转换、写入时有备份**。转换优先使用明确的 `subordinate/child` 信息；不足时根据现有层级和节点类型推断，遇到多父或环则落入“待归属”分组，标记需人工审阅，绝不默默丢边。保留原有语义边及 `metadata_refs`。先对 200 句样本输出迁移差异报告，再允许批量升级；快照历史维持可读。

### 3.2 输入与处理状态分离

`POST /api/utterances` 保持按 `meeting_id + utterance_id` 幂等，但响应明确返回 `state=accepted|processing|committed|failed`、`meta_id`、`board_version`（仅 committed 有值）；重复请求返回**同一条事件的当前状态**。增加 `GET /api/utterances/{id}/status?meeting_id=` 或等价的批量状态接口，WebSocket 发状态变化。前端只在 `committed` 后显示“已整理进看板”；`accepted` 表示原话已安全接收；`failed` 保留重试按钮与错误摘要。记录 `processing_state`、`attempts`、`last_error`、`updated_at`，重启扫描 pending/processing 做幂等恢复。

实时 ASR 采用**静音切分后的 final segment 作为正常落图单位**；临时字幕只展示不入库。完整录音的 SenseVoice 结果只用于“没有成功分段时的兜底”或用户明确发起校正；不能与已落图分段盲目再次提交。每分段有稳定 ID、序号、起止时间和提交状态；失败分段保存在浏览器待发送队列，刷新后可恢复，成功确认后删除。停止录音时必须报告尚未发送的分段数，并提供重试或导出文本。这一目标替代[实时转写旧设计](../specs/2026-09-25-live-asr-design.md)中的“整段 final 是唯一落图事件”，实施时要更新旧设计和 README。

### 3.3 人工修改、证据和版本

人工编辑 API 接受 `expected_version`，冲突返回 409 与最新数据，前端保留草稿供用户比较重试。字段级 `manual_override` 覆盖文本、类型、父级、重要性、完成状态；AI 仍可追加证据和新关系，不能静默改受保护字段。每次修改记录操作者、时间、字段前后值、理由与来源；“撤销”生成新版本，不擦掉历史。没有原话的手工节点应明确标注“人工创建”；模型判断低置信度要标注“待确认”。

### 3.4 会议生命周期与结果状态

会议状态为 `draft → live → ended`；录音停止不自动等于会议结束。`ended` 后仍可人工修正、重开，但自动输入需显式开启新会中阶段。结论至少区分 `proposed/confirmed/superseded`；待办至少有负责人、期限、状态；分歧由未关闭的反对关系或显式 conflict 节点共同计算，不能只数 `type=conflict`。没有负责人/期限的行动项显示“待补充”，纪要中也保留该缺口。

## 7. 关键风险与决策记录

| 风险 | 处理方式 |
| --- | --- |
| 旧图中的语义边无法唯一推断父级 | 提供迁移预览和“待归属”列表，不做无依据的自动改挂。 |
| 模型输出与人工编辑竞争 | 服务端字段级保护 + 版本检查 + 可撤销历史。 |
| 实时分段与整段终稿重复 | 单一正常落图路径、稳定事件 ID、兜底触发条件和状态查询。 |
| 200 句图谱信息密度过高 | 概览和议题树为入口，局部图按需展开，性能预算基于样本实测。 |
| Demo 被误当生产服务 | M0/M1/M2 分级发布，不把本地快照、Mock 或未测性能写成线上能力。 |
| Live2D 资源许可及外链依赖 | 内测保留静态降级；商用前取得适当许可或替换素材。 |
