# Live2D 看板娘集成设计

## 目标

将会议看板右侧当前的 SVG 机器人替换为 `A8Chann/dsh-pet-live2d` 仓库中的 DS 鲸鱼娘 Live2D 模型。模型成为当前会议网页的一部分，不接入 DSH 插件宿主；现有会议状态气泡、看板状态事件与其余页面交互继续工作。

## 用户体验

- Live2D 角色占据当前右侧看板娘区域，随视口尺寸自适应，不遮挡看板或录音控件。
- 模型眼睛/头部跟随页面鼠标；此行为由 Live2D 模型接管，移除 SVG 的眼睛追踪实现。
- 现有 `mascot_state` WebSocket 消息继续更新状态气泡，同时驱动模型播放最接近的已存在动作/表情。映射只使用模型实际声明的动作与表情；没有合适动作的状态仍更新气泡，并回到待机动作。
- 首版只做展示、注视和会议状态动作，不移植 DSH 专用右键面板、换装设置页、多宠物管理或桌宠拖拽功能。
- 窄屏仍沿用当前隐藏侧栏的布局，不额外覆盖移动端页面。

## 集成方案

1. 从公开仓库复用模型包与其必要的 MIT 许可代码/依赖。使用仓库目前采用的 PixiJS 和 `untitled-pixi-live2d-engine` 渲染路径，避免把 DSH 宿主适配层带入本项目。
2. 新建一个独立的前端看板娘视图/控制器，负责创建透明 Pixi 画布、异步加载模型、鼠标注视和销毁资源。`main.ts` 只连接该控制器与现有 `MascotController` 状态入口，不承载模型细节。
3. 保留 `MascotController` 的状态标签和气泡职责，并扩展其模型动作映射。用明确的加载状态处理初始化；组件卸载/页面关闭时释放 Pixi ticker、事件监听器和 WebGL 资源。
4. Cubism Core 是 Live2D Inc. 专有运行时，仓库未随代码提供，也不得从该仓库复制/再分发。优先按 Live2D 官方许可和 SDK 说明引用/加载该运行时；若加载失败或浏览器缺少 WebGL，则保留状态气泡并显示本地静态后备图，不影响会议录音和看板。
5. 固定并记录渲染依赖版本；模型资源附带来源、署名、许可和修改说明。不得把授权为非商业的模型描述为可商业使用。

## 降级与隐私

- Live2D 模型、引擎或 Core 加载错误只影响角色动画。右侧仍展示静态后备形象及当前状态气泡；其它看板能力不受影响。
- 仅在本地页面渲染模型；不上传鼠标坐标、状态事件或会议内容到模型供应方。
- 模型资源、专有运行时与依赖的体积需在实施前盘点，并记录初次联网加载对启动时间的影响。页面状态气泡不等待模型下载完成。

## 验收标准

1. 看板打开后可见 Live2D 鲸鱼娘，不再显示 SVG 机器人；加载期间及失败时均有可用后备视觉。
2. 鼠标在页面内移动时模型注视鼠标，离开后回到自然待机视线；角色区域不阻止看板和控件操作。
3. 收到现有各类 `mascot_state` 时，气泡文字与改动前一致，模型只播放存在的动作/表情；未知状态不会导致前端异常。
4. 页面窄屏仍保持侧栏隐藏，录音与看板核心功能不被角色画布遮挡。
5. 关于/鸣谢与许可文件准确记录资源署名、CC BY-NC-SA 4.0 限制、项目改动情况及 Cubism Core 的非再分发边界。
6. 前端 TypeScript 构建通过；测试覆盖状态到动作映射、渲染初始化失败降级、销毁清理和核心交互。浏览器中验证 WebGL 模型可实际绘制并能跟随鼠标/状态变化。
