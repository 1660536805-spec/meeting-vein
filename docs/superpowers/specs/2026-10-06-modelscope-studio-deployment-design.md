# 会脉魔搭创空间部署设计

## 目标

将现有会脉原型部署到魔搭创空间，产出评委可通过浏览器打开的在线体验链接。尽量保留原产品界面和本地开发启动流程；部署说明必须准确披露真实大模型是否启用及语音能力边界。

## 当前架构与约束

- 前端为 Vite 应用，开发时通过代理访问会议后端、WebSocket 和本地 ASR 服务。
- 会议后端与 ASR 服务当前仅绑定 `127.0.0.1`；前端/API/ASR 分别使用 5173、8000、9000 端口。
- ASR 使用 SenseVoiceSmall 与流式 Paraformer，运行时需要下载模型权重及 FunASR/PyTorch 依赖。
- 会议 LLM 通过 OpenAI 兼容配置启用；缺少配置时使用 MockLLM。
- 项目目录目前位于更大的 `/Users/leo` Git 仓库下，并作为未跟踪目录出现；不得在用户目录级仓库中暂存或提交无关内容。
- 魔搭 Docker 创空间要求应用监听 7860 端口；官方部署技能资料指出 Docker 创空间构建前需完成阿里云账号绑定和魔搭实名认证。

## 方案

采用 Docker 创空间承载现有全栈原型。构建轻量 Nginx 作为唯一外部入口，服务监听 7860：静态托管已构建前端，将 `/api`、`/ws`、`/asr` 分别反向代理到容器内的会议后端和 ASR 服务。容器入口负责启动并监控三个进程，任一必需进程退出时使容器失败，便于创空间日志显示故障。

ASR 模型首次启动时从模型仓库下载，优先使用创空间持久化缓存目录；如果平台提供的 CPU/内存无法稳定加载双模型，则保留文字输入与 Mock 演示路径，并在 README 清楚说明语音服务未就绪的状态。默认不写入真实用户录音或会议记录到仓库；运行数据放在容器可写目录，注明实例重启后的持久性限制。

真实 LLM 密钥不进入代码、镜像或提交记录。初始创空间不配置密钥时使用 MockLLM；后续若账号已具备可用兼容 API，再通过创空间私密环境变量启用。部署 README 解释两种模式，避免将 Mock 输出呈现为真实模型推理。

## 部署产物

- 创空间 Docker 部署配置（端口 7860）。
- Dockerfile、单容器启动/代理配置，以及必要的忽略规则。
- 更新后的部署 README：创建要求、启动行为、模型下载与数据边界、LLM 演示/真实模式说明。
- 可分享的创空间应用地址。

## 验收标准

1. 本地容器可构建并在 7860 提供页面；静态资源、API 和 WebSocket 路径均可达。
2. 创空间日志显示前端和后端服务正常启动；在线页面能打开并完成文字输入到看板更新的体验。
3. ASR 启动成功时页面可显示语音模型状态；失败时仍可清楚提示且文字演示可用。
4. 未在上传/提交文件中包含 `.env`、访问令牌、API 密钥、个人数据或本地模型缓存。
5. 最终 README 和报名链接说明 AI 模式和在线体验边界。

## 风险与边界

- Docker 构建与模型首次下载耗时、内存需求受平台资源及网络影响，需以创空间实际构建/运行日志验证。
- 是否能选择足够资源、公开创空间并正常构建，取决于账号实名/绑定状态及平台配额。
- 当前设计不引入新产品功能，不迁移到 Gradio，也不将音频或会议内容发送到外部服务。
- 创空间的代码可见性以创建时的公开/私有设置为准；为获得评委可访问的体验链接，需在创建页确认公开可访问选项。
