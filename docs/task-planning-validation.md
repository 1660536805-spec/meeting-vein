## 需求逐项核对

| 约定需求 | 实现与证据 |
| --- | --- |
| 会议结束后整理已有任务，不任意发明工作 | 真实客户端读取当前行动项与原话；提取任务必须通过来源校验。`test_extraction_requires_verbatim_current_meeting_source` 验证伪造与跨会议来源会被拒绝。 |
| AI 提出日期和依赖，先由人核对 | 生成只保存草稿；拓扑排序安排缺失日期并标记建议。`test_model_scheduling_and_missing_date_proposals` 验证平行任务和先后日期。 |
| 修改负责人、日期、前置任务后确认 | 页面可编辑并保存草稿；缺字段、日期冲突、自依赖或循环时拒绝确认。独立示例会议实测完成三个任务的编辑、保存、确认。 |
| 任务依赖图可视化 | 使用原有 X6。实测「完成需求方案 → 开发交互原型 → 录制比赛演示」连线、分工、日期、状态均可见。 |

| 新草稿不覆盖正式进度 | `test_full_lifecycle_replacement_draft_preserves_progress_and_exports` 验证生成和再次确认都保留同一任务的正式进度。 |
| 只围绕本次会议和计划问答，能核对来源 | 示例查询执行顺序，展示三项任务与原话引用；测试拒绝不属于当前会议的引用。来源文本按纯文本显示，不执行 HTML。 |
| 导出与持久化 | 浏览器实际下载 Markdown，文件包含分工、日期、依赖、完成状态与来源 ID；会议纪要使用正式计划的分工字段，JSON 快照含草稿/正式计划。写失败与重启回读均有测试。 |

## 画布裁切与全屏补充验收

- 原问题已在同一示例会议复现：530px 宽窗口从任务计划切回关系图时，根节点左边界为 -19.98px，被画布截掉。
- 画布尺寸变化时保留最近可见节点的相对位置并留出边界，不再自动改写用户缩放；回归测试覆盖缩窄、重复尺寸通知、零尺寸和观察器清理。
- 修复后，530px 窗口按「任务计划 → 关系图」切换，根节点四边均位于画布内。
- 三种视图共用上方「画布全屏」入口；桌面、手机均可访问。图谱增加「适应画布」，只调整视角、不重新排版节点。
- 浏览器实测原生全屏：`fullscreenElement` 为 `board-shell`，容器覆盖 1470×923 视口；适应画布后七个节点均完整位于画布内。按钮退出和原生 Esc 退出均验证。
- 390×844 下模拟浏览器不支持全屏 API，验证页面全屏覆盖整个视口、按 Esc 退出、恢复原滚动状态。临时 API 修改和视口模拟均已恢复。
- 本机截图：`.amo_deploy/graph-fullscreen.jpg`、`.amo_deploy/fullscreen-mobile.jpg`；前端测试和构建日志：`.amo_deploy/fullscreen-tests.log`、`.amo_deploy/fullscreen-build.log`。运行资料不纳入 Git。
- 自审结论：节点裁切修复、可找到的全屏入口与退出路径已完成。大图全部适配时文字会变小，仍需使用缩放和拖动画布阅读；尚未做 Safari 与真实手机的兼容性测试。

## 验证边界与自审结论

软件流程已跑通。真实模型接口、JSON 结构校验和引用检查通过注入客户端输出验证；本机当前使用规则演示，没有真实模型请求成功或提取效果的证据。正式参赛前应配置模型，再用真实小组会议评测任务遗漏、错误负责人、错误依赖、日期冲突和问答引用准确性。

本版本是单机的小组会议工具，未实现成员登录或异地在线协作。文件并发保护只覆盖单进程服务；这次没有宣称多进程、真实录音到真实模型、真实麦克风或公网生产部署已验证。
