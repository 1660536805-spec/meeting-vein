## 0. 满分逻辑（先看这一节）

**满分不等于再加功能，等于把已有能力"证据化"。**

核对代码后发现一个关键事实：会脉的**后端能力比外表现完整得多**——`backend/app/server.py` 已经具备
节点锁定（`/api/node/{id}/lock`）、重要性（`/api/node/{id}/importance`）、合并（`/merge`）、
撤销（`/undo`）、版本回滚（`/rollback`）、纪要（`/minutes`）、结束预览（`/close-preview`）、
快照（`/snapshot`）、v2 迁移接受/回滚（`/migration-accept|rollback`）、失败重试（`/retry_pending`）。
**这些能力大多没有在前端闭环，也没有被整理成评委能看到的证据。**

于是失分点集中在三处，都不是"算法不行"：

| 失分类型 | 现状 | 后果 |
|---|---|---|
| **不可访问** | 只有 `127.0.0.1` 本地 Demo，无在线地址 | 评审无法验证 → 功能完整性、应用价值直接失血 |
| **不可量化** | 真实 LLM 质量报告 `not run`，`llm.calls=0` | 创新性、技术实现进不了高分段 |
| **不可复核** | 四大件（说明文档/演示视频/算法说明/测试报告）未归档齐全，附录缺失 | 方案完整性卡在中间档 |

**满分公式：能跑 → 评委能打开 → 能量化 → 能复核 → 能归档。**

## 1. 六维满分达成条件

### 1.1 创新性（20 分）｜顶档＝"全新 AI 技术架构或模式，解决行业重大难题，具有开创性"

| 评委要看到 | 我们必须给出 | 现状 |
|---|---|---|
| 一个**可命名的算法贡献**，不是"我们用了 LLM" | 把「双 Agent 增量建图」正式命名并形式化：*Two-Agent Incremental Graph Construction*。给出定义：`Gₜ = Apply(Syncer(Analyzer(uₜ, Cₜ₋₁), Gₜ₋₁), Oₜ)`，并说明与传统"整段摘要"的区别 | 已有实现与雏形公式，但未作为核心贡献对外命名 |
| **行业重大难题** ↓ 被明确解决 | 把痛点从"会议效率"升级为**"决策血缘（decision lineage）不可追溯"**：观点如何被支持/反对/取代、结论为何改变，无系统化记录。会脉用 `support/oppose/duplicate/replace` 四类语义边建模 | 设计文档有，但对外表述偏"会议记录" |
| **量化对比**证明开创性 | 会脉 vs 基线（单轮摘要）：在权益归属、重复归并、相悖召回、来源可追溯率四项上做对比表 | 缺 |
| 「取代边」保留演进痕迹的独特性 | 单列一节说明"不静默覆盖、不阻断，保留决策演进轨迹"，配图示 | 有设计，缺对比论证 |

**必交**：核心算法说明书（含形式化定义、复杂度、与基线对比表）。

### 1.2 技术实现（20 分）｜顶档＝"算法科学、选型合理、运行高效稳定、交互流畅、AI 与系统适配性极佳"

| 评委要看到 | 我们必须给出 | 现状 |
|---|---|---|
| 模型选型**有依据** | 说明为何 ASR 选 SenseVoiceSmall+fsmn-vad（中文、流式、本机可跑）、LLM 用 OpenAI 兼容可插拔（deepseek-chat 实配）、VAD 静音切分策略 | 有实现与文档，需成表 |
| **运行高效稳定**有数据 | 性能基准（200 句首屏 36ms / 500 句 81ms 已有）+ 补：端到端时延、P95、1000 节点、异常恢复演练 | 部分有 |
| **真实链路端到端验收** | 真实麦克风 → 识别 → 上板全链路录屏 + 时延数据（README 自认未完成） | **缺，是硬伤** |
| **系统稳定性**可证 | 幂等（按发言 ID 去重）、失败重试、`accepted/processing/committed/failed` 状态机、崩溃恢复演练记录 | 后端有幂等与重试，状态机契约已有文档，前端回执未闭环 |
| **适配性极佳** | 架构图展示 AI 模块与业务系统的数据接口（统一 `NormUtterance` 事件）+ 字段级人工保护 | 有 |

**必交**：测试报告（功能/性能/异常恢复三类）+ 端到端验收记录。

### 1.3 功能完整性（20 分）｜顶档＝"功能完整、满足核心需求、流程流畅、无明显缺失"

**验收标准就是仓库自己的 M1 定义**：建会 → 议程 → 输入 → 纠错 → 结束 → 纪要导出，全链路通过。

| 缺口 | 必做 | 依据 |
|---|---|---|
| P0 观感缺陷（已复现） | 修：发言人 `user_` 前缀、时间全 `00:00`、已加载会议仍显示"等待讨论" | 优化方案 P0-04 |
| 输入端回执不真实 | 前端区分"已接收原话／等待分析／已更新看板／失败可重试"，失败保留同 ID 可重发 | P0-05、utterance-state 契约 |
| 人工修正闭环不全 | 把已有的 `/lock`、`/importance`、`/merge`、`/undo`、`/rollback` **接到前端**，实现改名/改类型/改父级/锁定/撤销 | P1-03 |
| 结构树 vs 语义边混用 | 统一图数据契约（主父级 `parent_id` + 多条语义边），避免多父/循环 | P1-01 |
| 议程导入 | 会前议程文本 → 顶层议题骨架 | FR-PRE-01 |
| 模式标识 | 界面清晰标注 示例数据／Mock／真实模型 | P0-06 |

**必交**：功能演示视频（走完整故事线：概览→焦点→反驳→原话→人工修正→新发言更新→导出）。

### 1.4 方案完整性（20 分）｜顶档＝"覆盖开发全流程、内容完整、逻辑清晰、图表规范"

现状最好的项（`output/docx/会脉—官方模板作品方案.docx` 已按官方模板重排），补齐即可满分：

- **正文**：对照官方大纲六大项逐条核对无缺项（产品概述与定位／技术架构与创新／功能设计与实现／开发测试与部署／应用价值与展望／附录）。
- **图表规范**：架构图、算法链路图、数据流图、评分对照图统一风格并编号（已有"双智能体增量建图算法.png"可复用）。
- **附录**：核心术语表（已有）＋**核心代码片段**＋**测试原始数据**＋**参考文献**＋**佐证材料**。

### 1.5 应用价值（15 分）｜顶档＝"有效解决行业实际痛点、适配性强、市场需求/商业转化/社会价值"

## 3. 四阶段冲刺路线（按投入产出排序）

### 阶段 A｜可访问（最高优先，决定其余所有分数能否被验证）
1. 落地魔搭创空间部署：按 `docs/superpowers/plans/2026-10-06-modelscope-studio-deployment.md` 创建 `Dockerfile` / `docker/nginx.conf` / `docker/entrypoint.sh` / `.dockerignore`；Nginx 在 7860 同源代理 `/api`、`/ws`、`/asr`。
2. 容器烟测：`/`、`/workspace.html`、`/api/status`、文字输入→看板更新一轮。
3. 发布公开创空间，把链接写进 README 与报名说明。
   > 注意：容器默认 MockLLM 演示（不打包密钥/会议数据/模型缓存），说明文档必须披露 Mock 与真实的区别。

### 阶段 B｜可量化
4. 跑真实 LLM 质量评估：以 `backend/tests/annotations/debate-200-gold.csv` 为金标，`backend/scripts/evaluate_candidates.py --mode real --predictions <jsonl>` 生成准确率。
5. 扩充标注：为「方案讨论200句」「任务安排200句」补金标（现仅辩论有），覆盖三类会议。
6. 真实麦克风端到端验收：跑 `backend/tests/debate_e2e.py`（真实 LLM）+ 页面录音录像，记录时延。
7. 出具**测试报告**：功能 / 性能 / 异常恢复。

### 阶段 C｜可交付体验
8. 修 P0 观感（`user_` 前缀、00:00、"等待讨论"）。
9. 前端接出人工修正闭环（lock/importance/merge/undo/rollback）。
10. 统一图数据契约，消除结构树/语义边混用。
11. 剪功能演示视频。

### 阶段 D｜可复用价值
12. 收 2–3 场真实会议试点反馈。
13. 完善作品方案附录与佐证材料。
14. 更新答辩 PPT 与总结展望。
