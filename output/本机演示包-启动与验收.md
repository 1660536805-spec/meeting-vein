# 会脉本机演示包

从仓库根目录运行。需要 Python 3.12、Node.js/npm；语音模式还需要 ffmpeg 和 `local_asr/.venv` 模型环境。

## 首次安装

从源码包解压后可运行 `bash scripts/install_local.sh` 一次安装文字演示依赖；需要 Python 3.12、Node.js 20.19+/22.12+/24+ 和 npm。需要语音模式时运行 `AMO_INSTALL_ASR=1 bash scripts/install_local.sh`，并预先安装 ffmpeg。干净提交发布包运行 `bash scripts/package_local_demo.sh`；当前工作区含未提交改动时运行 `bash scripts/package_local_demo.sh --working-tree`，生成明确标注基线提交和工作区内容的源码快照。两种包都附 SHA-256 校验文件，不附带虚拟环境或模型权重，首次安装仍需联网获取依赖。以下是等价的手工安装命令：

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
cd frontend && npm ci && cd ..
```

## 轻量文字演示（推荐先跑通）

```bash
AMO_SKIP_ASR=1 bash scripts/start_local.sh
```

2026-10-11 本机烟测：此命令成功启动后端与 Vite；`/api/status`、`/history.html`、`/workspace.html` 均返回 HTTP 200。轻量模式下语音状态请求会显示服务不可用，这是预期状态；需要语音演示时使用下方完整模式。

浏览器打开 `http://127.0.0.1:5173/`，创建会议并设议程。右侧“会前准备”可上传 UTF-8 TXT、Markdown、带可选中文字的 PDF，确认待决问题；文字输入发言后，可以审核决策卡并给行动指定负责人和期限。结束会议前检查未确认结论、分歧、缺项行动与待决问题。导出纪要和本地快照后可查看来源与人工变更。

创建第二场会议后打开“历史”，选择新会议。在“跨会复盘”先检查按匹配度排序的延续议题候选；输入会议名、议题名或证据词（例如不带空格输入“华东区”）可以检索默认列表之外的旧会议。即使关键词只出现在旧会原话中，也会显示“搜索命中旧会议资料”，填入旧议题后由主持人选择本会议议题。语义候选会并排展示两场会议中最相关的原话摘录，便于先核对证据。选择候选只会填入表单，核对两边议题、填写关联人和原因后才会建立链接。时间线展示旧决议、新证据、新决议及上次未完成行动；系统不会自动合并议题。

会议看板的决策候选可回到原话。显式反驳即使被挂在不同议题下也会提示，并标出两侧议题供复核；同议题原话中的远程办公/固定坐班立场、数据安全风险/防护措施和幸福感/孤独结果也会生成待核对线索。错误的议题归属建议可以按本场会议隐藏，也可恢复；实际改挂仍要人工编辑保存。候选分数是词项重合度，不是模型置信概率；规则线索也不是事实判定。重复候选还会提示同一办公立场在总结中的重复陈述。主持人核对原话后才可添加反对关系或合并节点。

行动日历订阅中的逾期事项从下一个可用的本地 09:00 起每日提醒，避免从原截止日生成历史重复事件；单次下载只生成下一次提醒。提醒是否显示仍取决于日历客户端的刷新策略，订阅期间本机服务需保持运行。

外部任务推送默认未配置。在 `backend/.env` 设置 `AMO_TASK_WEBHOOK_URL` 后，行动台账会出现“同步到任务工具”按钮；可用 `AMO_TASK_WEBHOOK_TOKEN` 配置接收端 Bearer token。系统按会议名、任务标题、负责人、期限、状态等完整外发内容记录指纹；内容没变就不重复推送，只改看板中的任务标题也会重新同步。失败后保留上次成功记录，可再次点击重试。接收端需要用稳定 `external_id` 更新任务，并根据 `idempotency_key` 去重。该功能提供通用 Webhook 契约，需由团队配置自己的自动化/任务接收器；当前没有厂商账号或真实远端回执可验收。

## 完整语音演示

先按 README 安装本机 ASR 环境，再运行 `bash scripts/start_local.sh`。首次模型下载和加载需要时间。若 5173 端口已占用，可设置 `AMO_FRONTEND_PORT=5176`。

语音面板默认勾选“人工核对后入板”。实时切分后，每段可分别修订文本、填写发言人并确认；完整录音终稿显示为遗漏核对参考，最后一段确认后，所有已确认分段按时间顺序送入看板。发言人名称由使用者逐段指定，当前没有自动说话人识别。若关闭核对选项，实时分段会直接入板。刷新页面会恢复尚未确认的逐段草稿。

- 代码检查：后端 unittest、前端 Vitest 与构建通过；实际麦克风、不同机器安装和长时会议还需现场验收。
- 真实缓存模型与仓库样例音频的本机 ASR 烟测见 `doc/reports/local-asr-smoke-2026-10-11.md`；流式样本 P95 为 1142.7 ms，不能作为真实麦克风到上板时延。
- 真实抽取质量见 `doc/reports/candidate-quality-report-2026-10-10-v2.md`；它是当前模型的实际测量，尚不达 20 分目标。
- 双人标注与真实用户试用目前无人执行；见 `backend/tests/annotations/labeling-protocol.md` 和两份空白标注队列。请由真实参与者记录，不要填造结果。
- 现场麦克风、人工修订、结论复核、行动日历、导出和跨会关联的步骤见 `doc/reports/现场试用与双人标注流程-2026-10-11.md`。
- 会议数据位于 `backend/.amo_data/`，复制目录即可备份本机演示数据；快照 JSON 包含材料摘录、发言和看板，请按会议资料管理。
